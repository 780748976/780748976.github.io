混合检索到底值不值得用？一份 dense / RRF / rerank 的对照实验

“加了 BM25 和 rerank，检索效果一定更好吗？”——这句话在 RAG 项目里几乎成了默认假设。但跑一次正经的对照实验你会发现：有时候加了反而更差。

本文先用一个小例子把 Hit@K、MRR、Recall@K、nDCG 讲到能自己算出来，再用一个在两个数据集上跑的对照实验，回答”混合检索到底什么时候才值得用”。

阅读前置：知道”向量检索””BM25””rerank”大概是什么就够了。

一、先搞懂指标：Hit@K / MRR / Recall@K / nDCG

比较检索好坏，得先有标尺。检索评测的核心思路极简：

给你一个 query，已经标注好哪些文档相关（叫 qrels）。你把方法返回的排序列表拿来，按”相关文档排得有多靠前”打分。

下面用一个贯穿全文的小例子。假设：

  • query：检索一个医学问题
  • 标注的相关文档（qrels）：{D2, D5}（只有这两篇相关）
  • 某方法返回的 top-5 排序：[D1, D2, D3, D6, D5]

两个相关文档 D2、D5 都在 top-5 里，但都不在第一位（D2 排第 2，D5 排第 5）。下面四个指标分别从不同角度给这个结果打分。

1.1 Hit@K —— top-K 里有没有”中”

最直观。top-K 个结果里只要有一个相关文档，就算命中，记 1；否则 0。 对所有 query 求平均。

指标 计算 值
Hit@1 {D1} ∩ {D2,D5} = ∅ 0
Hit@3 {D1,D2,D3} 含 D2 1
Hit@5 {D1,D2,D3,D6,D5} 含 D2,D5 1

Hit@K 只看”有没有”，不看”排第几”。它衡量的是召回体验——用户翻 K 条能不能找到答案。

1.2 MRR —— 第一个相关的位置

MRR（Mean Reciprocal Rank）关心第一个相关文档排在第几位，取其倒数。排得越靠前分越高。

本例第一个相关是 D2，排第 2，所以 RR = 1/2 = 0.5。若 D2 排第 1 → 1/1 = 1.0（满分）；若 top-K 里一个相关都没有 → 0。MRR 就是所有 query 的 RR 平均值。

MRR 适合”用户只看第一条”的场景（问答、搜索首条）。它只看第一个相关，后面的相关文档排第几不影响分数。

1.3 Recall@K —— 相关文档召回了多少

它衡量”漏没漏”。本例总相关 2 个（{D2,D5}）：

指标 计算 值
Recall@3 top3 命中 {D2} = 1 / 2 0.5（漏了 D5）
Recall@5 top5 命中 {D2,D5} = 2 / 2 1.0（全召回）

Recall 和 Hit 的区别：Hit 只要有 1 个就 1.0；Recall 看召回比例。当相关文档多（一个 query 有十几篇相关）时，两者差别巨大——Hit@10 可能满分，Recall@10 才零点几。

1.4 nDCG@K —— 排得多好（带位置折扣）

最”重”也最常用的指标。核心思想：相关文档排得越靠前越好，且位置越靠后贡献衰减越快（对数折扣）。

本例用二值相关性（相关记 1，无关记 0），只有 D2（rank 2）和 D5（rank 5）有贡献：

nDCG 同时考虑”有没有”和”排第几”，还用对数折扣区分”第 1 名”和”第 5 名”的价值，是 IR 评测的事实标准（BEIR、MTEB 排行榜都用它）。本文后面重点看 Hit@K、MRR、nDCG@10。

四个指标速查

指标 关心什么 本例值（K=5）
Hit@K top-K 有没有相关 1
MRR 第一个相关排第几 0.5
Recall@K 相关召回比例 1.0
nDCG@K 排序整体质量（带折扣） 0.624

一句话记忆：**Hit 管”有没有”、MRR 管”第一条在哪”、Recall 管”漏多少”、nDCG 管”整体排得多好”**。

二、实验设计：要回答什么问题

核心问题：混合检索（dense + BM25 用 RRF 融合）和 rerank 精排，到底有没有用？什么时候有用？

设计三组方法，在同一批 query、同一套文档向量上公平对比：

方法 流程
dense 纯向量检索（embedding 余弦相似度）
hybrid_rrf 向量检索 + BM25 → RRF 融合
hybrid_rrf_rerank RRF 融合的候选 → rerank 模型精排

RRF（Reciprocal Rank Fusion） 是最常用的多路融合法，不看分数只看排名：

把向量检索和 BM25 各自的结果按”排名倒数”相加再排序，简单粗暴但很有效——因为两路用的打分尺度完全不同（余弦 vs 词频），直接比分数没意义，比排名才公平。

两个数据集（BEIR 基准），故意挑特性相反的：

数据集 领域 特性 dense 预期
SciFact 科学论文 claim ↔ 论文，纯语义匹配 强
nfcorpus 医学 专业术语，词面匹配重 弱

技术栈：Qwen3-Embedding-4B（向量）、rank_bm25（词法）、RRF（融合）、Qwen3-Reranker-4B（精排）。指标用 ranx（TREC 标准评测库）计算，确保口径权威。每个数据集跑全部有标注的 query（SciFact 300 条、nfcorpus 323 条）。

三、结果：两个数据集，两种结局

3.1 SciFact（语义匹配，dense 强）

方法 Hit@1 Hit@10 MRR@10 Recall@10 nDCG@10
dense 0.6267 0.8933 0.7076 0.8867 0.7447
hybrid_rrf 0.6167 0.8667 0.6983 0.8526 0.7281
hybrid_rrf_rerank 0.6933 0.9233 0.7620 0.9166 0.7957

dense 已经很强（nDCG@10 = 0.74）。加 BM25+RRF 不仅没提升，反而略降（MRR 0.708 → 0.698，nDCG 0.745 → 0.728）。只有再叠一层 rerank 才把指标拉上去（MRR +5.4%）。

3.2 nfcorpus（词面匹配，dense 弱）

方法 Hit@1 Hit@10 MRR@10 Recall@10 nDCG@10
dense 0.4396 0.7028 0.5255 0.1640 0.3385
hybrid_rrf 0.5139 0.7554 0.5896 0.1726 0.3581
hybrid_rrf_rerank 0.5449 0.7926 0.6395 0.2081 0.4254

dense 明显变弱（nDCG@10 只有 0.34）。这一次 RRF 立刻有用：Hit@1 从 0.44 升到 0.51（+7.4 个百分点），MRR +6.4 个百分点。rerank 更是大涨（nDCG +25.7%）。

（nfcorpus 的 Recall@10 整体偏低是数据集特性：每个 query 相关文档很多，top-10 只能覆盖一小部分，不是实现问题。）

四、洞察与实践建议

把两个数据集并排放，规律立刻浮现：

数据集（特性） dense nDCG@10 RRF vs dense rerank vs dense
SciFact（语义，dense 强 0.745） 0.745 ↓ 略降 −1.7% ↑ +6.8%
nfcorpus（词面，dense 弱 0.339） 0.339 ↑ +5.8% ↑ +25.7%

洞察一：RRF 不是万能的，增益取决于 dense 的强弱

dense baseline 越弱、词面信号越重要，BM25+RRF 的增益越大；dense 已经很强时（SciFact），BM25 的词面噪声反而是负贡献，硬融进来会拉低排名。

直觉解释：SciFact 是”判断一句科学 claim 对不对”，靠的是语义理解，关键词重叠未必意味着相关；nfcorpus 是医学检索，病名、药名这些专业术语的字面匹配本身就是强信号，BM25 正好用得上。

洞察二：rerank 始终稳健，是最可靠的增益来源

不管 dense 强弱，rerank 都涨。而且 dense 越弱，rerank 增益越大（SciFact +6.8% vs nfcorpus +25.7%）。因为 rerank 模型用 query 和每篇候选做精细的交叉注意力打分，能把 dense 漏排的好文档重新顶上来——候选池越”乱”，它越能捡漏。

实践建议

  1. 先看 dense baseline 强不强。跑一遍纯向量检索，看 nDCG/Hit。
  2. dense 已经很强（>0.7）：别折腾 BM25+RRF，直接上 rerank 就行，省一层计算。
  3. dense 偏弱（专业领域、术语多）：dense + BM25 RRF 再 rerank，三者叠加收益最大。
  4. **别迷信”混合检索一定更好”**。它是条件性的，关键变量是”你的 dense 检索够不够强”。

五、关于可信度：用权威库复现过

为了排除”是不是自己写的 RRF 或指标算错了”，这套实验同时跑了两个版本：手写的 RRF + 指标，和用 ranx（指标经 TREC Eval 验证的工业库）的版本。两者结果逐项几乎一致（Hit / Recall / nDCG 分毫不差，MRR 仅因定义差异——mrr@10 截断 vs 全列表——差不到 0.005）。所以”RRF 在 SciFact 上没用”不是实现 bug，是真实的数据特性。

结语

这篇博客真正想传递的不是”哪个数据集赢了”，而是一个方法论：

  • 评测前先懂指标——Hit / MRR / Recall / nDCG 各有侧重，别只盯一个。
  • 结论要跨条件验证——在两个特性相反的数据集上跑，比在一个数据集上跑十遍更有说服力。
  • 混合检索是工具不是信仰——它的价值是有条件的，而 rerank 是那个几乎总值得加的层。

代码和数据都在 experiments/hybrid_retrieval/，可复现。
